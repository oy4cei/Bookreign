Apple identifies operating-system HTTPS as typically exempt from documentation upload; this is not a general conclusion about every publisher’s export obligations. [Apple encryption guidance](https://developer.apple.com/documentation/security/complying-with-encryption-export-regulations)

## Privacy data-flow evidence

| Data / activity | Current implementation and destination |
|---|---|
| Library, notes, locations, borrower names/history, selected cover photos | SQLite in Application Support (`LibraryStore.swift:17`, `LibraryDatabase.swift:20`); no publisher upload path found. JSON/CSV export is user initiated through Files; a chosen cloud file provider/system backup is managed separately. |
| Camera/OCR/photo import | Barcode/OCR image processing is on device. An extracted ISBN can become the search query (`AddBookView.swift:417–436`); a later catalog search sends that query. Do not imply that all derived text must remain on device. |
| ISBN/title/author lookup | Open Library receives lookup/search parameters over HTTPS (`BookCatalog.swift:153`, `:202`). MEGOGO receives canonical ISBN and subsequent product requests (`MBooksCatalog.swift:10`, `:29`). Remote hosts necessarily receive ordinary connection/request metadata, including IP address. |
| Displaying catalog covers | `BookCover` uses `AsyncImage` for remote HTTPS cover URLs (`App/Design.swift:29`). Requests may occur while browsing a saved library; not every network request is a separate search-button tap. |
| Alternative cover | Catalog query may contain ISBN/title/author. Direct image download follows HTTPS redirects, uses an ephemeral session and limits bytes; confirmed image is stored locally (`CoverEditor.swift:312–349`, `:377–406`). “Ephemeral” describes local session persistence, not remote server retention. |
| Google image search | `CoverSearch.webSearchURL` builds a Google query (`Sources/BookCatalog/CoverSearch.swift:25`), opened externally by user action. No embedded advertising/Google SDK was found. |

Apple defines collection for its label around transmission that permits retention beyond servicing the request in real time; on-device processing is excluded. Therefore, network use is neither automatically “collected” nor automatically exempt. [Apple App Privacy definitions](https://developer.apple.com/app-store/app-privacy-details/)

Before finalizing the label, determine for each built-in catalog/cover provider whether anonymous request/search logs persist, their purposes, whether records can be linked to a user, and whether any tracking occurs. MEGOGO’s [privacy policy §§3.2.1 and 6](https://mbooks.com.ua/about/polityka-obrobky-personalnykh-danykh/) describes search history and retention according to operational/legal needs, but does not resolve the app’s anonymous API scenario. Open Library/Internet Archive API log retention was not established in this audit. Do not invent a retention period or label category. If retention exists, select the applicable data types/purposes/linkage using actual provider facts; if it does not, retain supporting evidence. The source manifest currently supplies required API reasons and a no-tracking declaration; it is not a completed App Store Connect privacy questionnaire.

The localized metadata package passed validation of **21 fields**. These are prepared local materials; they have not been entered into an App Store Connect app record. Publisher identity/contact, public URLs and questionnaire/account decisions remain as listed above.

Use real app screens with fictional borrower information and local/generated cover designs. Open Library’s [catalog FAQ](https://openlibrary.org/help/faq/using) describes donated catalog data and CC0 contributions, while its [licensing page](https://openlibrary.org/developers/licensing) warns that contributions may have existing rights. Do not interpret metadata availability as a blanket right to use every publisher’s cover in promotional screenshots.

Review notes should explain no login is required, camera is optional, the manual path works offline, catalog coverage is incomplete, and backup restore replaces the library after confirmation. Supply reproducible navigation and a tested ISBN when a live catalog result is useful. Complete the current age-rating questionnaire from actual features and accessible catalog content; do not promise a particular rating before App Store Connect calculates it. Keep public descriptions within the shipped feature set. [Apple review requirements](https://developer.apple.com/app-store/review/guidelines/)
